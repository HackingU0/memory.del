# 安全规则与停止条件

## 动作分级

| 级别 | 例子 | 需要的确认 |
| --- | --- | --- |
| L0 只读 | 浏览、搜索、打开资料页、查看相册、读取列表 | 问询完成即可 |
| L1 可撤回 | 照片删到「最近删除」、移到「隐藏」、取消置顶 / 星标、移出自建相簿 | 该类别清单确认 |
| L2 本机不可撤回 | 删除聊天、清空聊天记录、删收藏、删通讯录联系人、删通话记录、删备忘录 / 日历事件、删收货地址或常用乘车人 | 该类别清单确认，执行前再报一次数量 |
| L3 ta 可能察觉 / 对外可见 | 删好友、拉黑、取关、删除自己发过的动态、退出或删除共享相簿、停止共享位置、移出家人共享、解除情侣空间 / 亲密关系、解绑亲属卡 / 亲密付 | **每一项单独确认**，说清后果 |
| L4 永久清除 | 在「最近删除」里永久删除 | 单独确认，需要用户完成 Face ID / 密码，只清本次删掉的项目 |

## 绝对不做

- 给 ta 或任何人发消息、打电话、发好友请求、点赞、评论、发帖、改签名，除非用户明确要求这一件具体的事。
- 在「最近删除」里用「全部删除」或「全部恢复」：里面有和 ta 无关的东西。
- 删除或退出群聊、删除工作 IM 里的同事关系，除非用户在问询时明确点名。
- 任何涉及资金的操作（转账、退款、解绑银行卡）；亲属卡、亲密付属于 L3，只在用户明确要求时处理，并提醒涉及额度和账单。
- 代替用户输入密码、验证码，或尝试绕过 Face ID。认证一律按 `iphone-use` 的认证接管流程交给用户。
- 碰 ta 的账号、ta 的设备，或用户不拥有的设备。
- 把照片、截图、聊天内容上传到任何地方或另存。用户选了「备份到 Mac」的除外。

## 停止条件

出现以下任一情况，停止当前动作，把看到的情况和可选做法告诉用户，等回答：

1. 身份不确定：同名、多个候选、资料与档案对不上、人物相簿里混了别人。
2. 候选把握程度是「存疑」，或者属于用户没说过的边界情况（多人合照、群聊消息、ta 和别人的合照、ta 送的礼物照片等）。
3. 将要执行的动作级别高于用户已批准的级别，或不在已批准的类别里。
4. 实际数量和计划不符：选中的数量和清单不一致，删除后的数量对不上，或者搜出来的结果明显多于或少于预期。
5. 界面和预期不一样：弹出没见过的对话框，确认文案里出现「所有设备」「所有参与者」「共享」「无法恢复」等字样，或者按钮位置看不清。看清截图前不要点确认。
6. 涉及共享：照片在 iCloud 共享图库或共享相簿里（删除会影响其他参与者，ta 可能就是参与者），备忘录、日历、提醒事项、文件是和 ta 共享的。
7. 需要认证：Face ID、密码、App 登录过期。按认证接管流程交给用户。
8. 工具返回 `uncertain`、`action_complete=false` 或超时：先读实际状态，不重放删除。
9. 用户在对话里表现出犹豫或改主意。

## 关于 iCloud 和同步

- 开了「iCloud 照片」时，在 iPhone 上删照片会同步删除所有登录同一 Apple 账号的设备和 iCloud 上的这张照片。执行前提醒一次。
- iCloud 共享图库里的照片，删除后所有参与者都看不到了。如果 ta 是参与者，这属于 L3，先问用户：是要删除，还是先移到个人图库，还是不动。
- 微信、QQ 等的聊天记录删除只影响本机，ta 那边、电脑版、其他手机、聊天记录备份都还在。汇报时如实说明，不要说成「对话已经从世界上消失」。

## 执行习惯

- 每批删除前读出已选数量，与清单对齐；删除后再读一次，确认少了对应数量。
- 一次只做一个类别，做完一类汇报一次。
- 动作结果不确定时，先读真实状态，绝不重放删除或确认。
- 用户随时说「停」，立刻停止，汇报进度。
