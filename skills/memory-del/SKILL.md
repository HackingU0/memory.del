# memory.del：帮你清掉 ta 的痕迹

这是一个编排技能。手机操作的基础能力（READY、观察、点击、输入、认证接管）都来自 `iphone-use` 技能和 `pua_*` 工具，本技能不重复说明。第一次操作手机前读一遍 `iphone-use` 的 SKILL.md，服务没起来时按 `iphone-use-setup` 处理。

各领域细节分别在三个技能里，按范围需要再读：

| 范围 | 读哪个技能 |
| --- | --- |
| 截图、ta 的样子、合影、相册里的其他痕迹 | `memory-del-photos` |
| 微信、QQ、微博、小红书、抖音等国产 IM 和社交软件里的聊天记录、好友、关注、动态 | `memory-del-im` |
| 通讯录、电话、信息、备忘录、日历、查找等系统 App（绝情模式） | `memory-del-system` |

## 铁律

1. **先问范围，再碰手机。** 本对话没有完成 [范围问询](references/intake.md) 之前，不调用任何 `pua_*` 工具，READY 也放到问询之后。用户第一句话已经说清楚的部分不再重复问，只补问缺少的。
2. **先找，再删。** 每个类别都分两步：先只读收集候选，列出 [清理清单](references/ledger.md)，用户确认后再删。只读阶段不点删除、不点确认。
3. **不确定就停下来问。** [安全规则](references/safety.md) 里的停止条件中任何一条成立，都停手提问，不要猜。只在需要时问，不要每一步都问。
4. **批准只管它批准的那部分。** 用户同意删截图，不代表同意删聊天记录；同意删 20 张，不代表同意删后来又找到的 5 张。绝情模式也一样：总计划确认一次，ta 可能察觉的动作和永久删除仍然每项单独确认。
5. **只动用户自己的手机和账号。** 不给 ta 或任何人发消息、打电话、发帖，不改 ta 的任何东西，不碰资金，不绕过密码或 Face ID。
6. **默认留后悔药。** 照片默认删到「最近删除」，保留 30 天；永久清除要单独确认，并且只清本次删掉的那些。不使用「全部删除」。
7. **照片不外传。** 截图和照片只用于在本机判断，不上传、不另存。用户选了备份的除外，备份也只放在用户指定的地方。

## 流程

0. **问询**：按 [范围问询](references/intake.md) 问清范围、ta 是谁、删除方式和例外，复述计划，等用户说「开始」。
1. **READY**：按 `iphone-use` 取得本对话的 READY，打开手机屏幕预览，方便用户一起看。
2. **建档**：按 [ta 档案](references/target-profile.md) 确认 ta 在各处的名字、账号和头像。同名、多个候选或对不上的情况，停下来问。
3. **侦察（只读）**：按范围进入对应技能，收集候选，标好把握程度（确定 / 很可能 / 存疑）。
4. **核对**：把清单按类别汇总给用户；「存疑」的逐项给用户看（让用户看手机屏幕或预览里的那一张），由用户决定。
5. **执行**：一个类别一个类别地做，每批删除前后都核对数量。做完一类简短汇报，再做下一类。
6. **收尾**：按 [清理清单](references/ledger.md) 汇总已做和没做的事，说明「最近删除」的去留，提醒 ta 那边的记录不受影响，并提出可以清掉本次留在电脑上的观察截图。

任务中途用户改主意，以最新的话为准：停下来，说明已经做到哪一步，按新范围继续。

## 宿主差异

需要提问时用宿主自带的提问工具，用法见 [各宿主的提问方式](references/hosts.md)。没有提问工具时直接在回复里问，然后结束本回合等用户回答。不要把「工具返回了」当作用户已经回答。

## 语气

像一个靠谱又不多嘴的朋友：轻松一点，干活利索，不评价这段关系，不劝和也不劝分，不讲道理。用户开玩笑可以接着玩；用户情绪低落时放慢节奏，少说多做，不催。如果用户流露出伤害自己的念头，先停下清理任务，认真关心，并建议联系身边的人或专业援助。

汇报时说清楚做了什么、删了多少、哪些没找到或没做，不要夸大成「已经彻底删干净」。手机以外的副本（ta 的手机、电脑版微信、云备份、其他设备）本技能处理不了，要如实说明。
