# 相册：截图、ta 的样子、合影

前提：已经按 `memory-del` 完成范围问询和 ta 档案，并取得本对话的 READY。本技能只处理用户选中的相册范围，规则以 `memory-del` 的安全规则为准。

「照片」App 的 bundle ID 是 `com.apple.mobileslideshow`。不同 iOS 版本的界面差异较大（标签栏、「精选集」、相簿入口的位置和名称都可能不同），下文路径只是参考，以实际观察到的界面为准；找不到入口时先截图观察，用搜索代替。

## 三个范围怎么区分

| 范围 | 定义 | 主要来源 |
| --- | --- | --- |
| 截图 | 「媒体类型 → 截屏」或屏幕录制中，内容和 ta 有关的：聊天截图、ta 的主页 / 朋友圈 / 动态截图、转账和通话记录截图等 | 文字搜索、界面结构、头像比对 |
| ta 的样子 | 画面里只有 ta（可以有风景、宠物、路人背景）的照片和视频，包括 ta 发给你后你保存的自拍 | 人物筛选、来源相簿、描述搜索 |
| 合影 | 画面里同时有 ta 和用户；有 ta 的多人照片按问询时的约定处理 | 人物组合、人物筛选后看人数 |

一张照片可能同时符合多个范围（例如合影的截图）。按用户选中的范围取并集；只选了其中一个范围时，属于其他范围的照片不动，拿不准的标「存疑」。

## 侦察（只读）

按 [匹配方法](references/matching.md) 选择信号。通常顺序：

1. **先用强信号**：人物筛选（ta 的人物、ta 与「我」的组合）、截图文字搜索（ta 的备注名 / 昵称 / 账号）、聊天截图标题。
2. **再用弱信号补漏**：地点、时间段、描述搜索、来源相簿、头像比对、时空邻近扩展。弱信号单独命中的一律最多标「很可能」，单一弱信号标「存疑」。
3. **逐张看图判断**：搜索结果只是候选。需要判断画面内容（单人还是合影、截图里是不是 ta）时，打开或放大到能看清，再用观察截图判断；不要只看缩略图上的模糊人影下结论。截图的识别方法见 [截图识别](references/screenshots.md)。
4. **记录位置**：记下每批候选在哪个视图里（某个人物、某次搜索、某个相簿）、日期和数量，执行时按同样的视图重新选中。

侦察过程中不点「选择」之后的删除、隐藏、移除，也不改人物名称。

## 核对与执行

- 按 `memory-del` 的清单格式汇总，「存疑」逐张让用户在手机上看。
- 用户确认后按 [删除步骤](references/deletion.md) 执行：一批一批选中、核对数量、删除、再核对。
- 删除方式按问询结果：删到「最近删除」（默认）、先 AirDrop 备份、移到「隐藏」，或彻底删除（L4，单独确认）。
- 照片在 iCloud 共享图库或共享相簿里时，先停下来问，见安全规则。

## 收尾（相册内）

按用户范围，询问是否也处理以下内容（都属于可选项，逐项问，不默认执行）：

- 「人物与宠物」里 ta 的人物：减少精选此人，或从人物中移除 / 隐藏。删光照片后人物可能自动消失。
- 「回忆」里以 ta 为主的回忆：删除这些回忆（只删回忆，不删照片）。
- 用户自建的、以 ta 为主题的相簿：删除相簿本身（照片已另行处理）。
- 共享相簿：退出 ta 创建的共享相簿；用户自己创建且 ta 是订阅者的，问是删除相簿还是移除 ta（L3）。
- 「重复项」：删完后看看有没有残留的副本。
- 「隐藏」相簿：需要用户完成 Face ID 后检查一遍，里面可能还有。
- 主屏幕上的「照片」小组件、「精选照片」：减少精选此人之后一般不会再出现，无需单独操作。
